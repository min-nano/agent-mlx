# ロードマップ

いま入っていないが、入れる価値がありそうなもの。順番は「効果 ÷ 手間」の見立て。

## 1. CI のビルド時間を縮める（最優先）

mlx-swift は MLX の C++ と Metal カーネルを丸ごとソースからビルドするので、
`build.yml` の各ジョブが 30 分以上かかる。いまキャッシュしているのは SwiftPM の
**取得済みソース**（`.spm`）だけで、**ビルド成果物はキャッシュしていない**。

理由は「壊れた増分ビルドの不可解な失敗を持ち込むより、素直に作り直すほうが
読みやすい」から。ただしビルドが安定して緑になったら、`DerivedData`
（`.derived`）のキャッシュを足す価値は大きい（30 分 → 数分）。足すときは

- キーに `project.yml` と Xcode のバージョンを含める
- 週 1 で強制的に捨てる（epoch をキーに混ぜる）
- 失敗したら一度キャッシュを消して再実行、を README に書く

をセットにすること。

## 2. 会話の共有・書き出しを画面から

`Transcript`（Markdown / テキスト）は Core にあってテストもあるが、GUI に
ボタンがまだ無い。**Core に機能があって GUI から届かない**のは CLAUDE.md の
方針に反するので、優先度は高い。

## 3. モデルの事前ダウンロード

いまは最初の送信でダウンロードが始まる。モデル画面から「先に落としておく」
ができると、外へ出る前に準備しておける（iPhone では実用上かなり効く）。
`MLXChatEngine.container(for:)` を分離すれば済む。

## 4. 速度の履歴

ベンチマークの結果を保存して、モデル × 端末の表にする。「MLX の実力を確かめる」
というこのリポジトリの目的そのものなので、本来は中心機能に近い。
`BenchmarkSummary` は Codable なので保存は簡単。

## 5. VLM（画像を渡す）

`mlx-swift-lm` には `MLXVLM` があり、`ChatSession` は `images:` を受け取れる
（いまは常に空を渡している）。写真を渡して説明させる、は iPhone でこそ面白い。
`ModelCatalog` に「画像が使えるか」の列を足すところから。

## 6. ツール呼び出し

`ChatSession` は `tools:` / `toolDispatch:` を持っている。いまは
`Generation.toolCall` を捨てている（本文に混ぜない）。ローカルモデルでどこまで
実用になるかは未知数だが、試す価値はある。

## 7. しきい値の ratchet up

`test.yml` のカバレッジしきい値は初期のベースライン（lines 90 / regions 85 /
functions 90 / diff 90）。実測が安定したら上げること。下げてよいのは、
「テストしない」と決めた層を除外に足したときだけ。
